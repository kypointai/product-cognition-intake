# 商品认知录入规范 · 严格冒号软标签(唯一契约源)

> 本文件是录入格式的**唯一事实源**。录入助手(`system-prompt.md`)、Python `intro_parser.py`、Java `IntroSoftSpecParser` 三处必须与本文严格对齐。
> 对齐产品方案 `AI导购系统产品方案V1.0` §4.3 商品认知卡。当前版本 **v4.3**(见 `changelog.md`)。

## 1. 基本格式

- 每项**独占一行**,格式 `标签名：内容`;标签名必须在**行首**,值可跨多行直到下一个行首标签。
- 冒号统一中文 `：`(英文 `:` 兼容)。
- 多值统一中文 `；`(`;` / 换行兼容)。
- 只用 §2 / §2.2 的标签,**标签名一字不差**。

### 1.1 标签顺序(v4 起固定)

```
商品名称：…
【扩展区】型号 / 规格参数 / 适用年龄 / 资质 / 卖点依据(§2.2)
【基础区】定位 / 核心卖点 / 关键事实 / … (§2)
```

- **扩展区必须紧跟 `商品名称：`、放在第一个基础区标签之前**。现有两处解析器还不认识扩展区标签:放在这里会被当作"商品名称"的边界内容忽略,原文保留在 `ai_product_intro`;若放到基础区标签后面,会被并进上一个标签的值,污染现有数据。
- 没有 `商品名称：` 时,扩展区放在全文最前面(第一个基础区标签之前的文本同样被忽略)。

## 2. 基础区标签

| 标签(别名) | 目标字段 | 必填 | 值格式 |
|---|---|---|---|
| `商品名称：`/`名称：` | 边界占位(不进产物、不计入 N) | — | 单值 |
| `定位：` | positioning | **必(skill 层面)** | 单值一句话,写法见 §4 规则 5 |
| `品牌：` | brand（参考，以 ai_brand 为准） | 选 | 单值 |
| `核心卖点：`/`卖点：` | selling_points[]（营销主张 is_claim=true） | **必** | 多值 `；` |
| `关键事实：`/`商品介绍：` | facts[] + summary 原料 | **必** | 每条带 `(来源)`,来源取 §4 规则 1 的固定列表 |
| `能力：` | capabilities[{name,evidence[]}] | 选 | `能力名(证据1；证据2)` 或 `能力名<-证据1；证据2`；证据可省(只写能力名)；多能力换行 |
| `使用感受：`（别名 `口感：`/`肤感：`/`手感：`/`气味：`） | sensory | 选 | 一句话；主要用于文案(弱检索) |
| `使用建议：`/`食用建议：` | usage_tips | 选 | 多值 `；`；只写用法,不写疗效 |
| `适用人群：` | audience（落库·人群过滤规划中） | 选 | 多值 `；`；只写资料声明或规格决定的人群,通用商品不写,见 §4 规则 4 |
| `适用场景：`/`场景：` | scenarios（落库·帮"被搜到"） | 选 | 多值 `；`；只写资料写到的或商品直接用途,见 §4 规则 4 |
| `功效：`（仅保健营养类） | efficacy（落库·帮"被搜到"） | 选 | 多值 `；`（如 助睡眠/补钙）；普通商品不写,见 §4 规则 6 |
| `推荐关键词：`/`关键词：` | keywords[] | 建议 | 3-8 个 `；` |
| `禁用表达：` | guardrails.disallow[] | 条件必(§4 规则 11) | `；` |
| `允许表达：` | guardrails.allowed[] | 条件必(§4 规则 11) | `；` |
| `常见问题：` | qa[{q,a}] | 选 | `问？答` |
| `需求：`/`解决问题：` | cognition.needs[] | **建议** | 多值 `；` |
| `用户会问：`/`搜索说法：` | cognition.query_phrases[] | 选 | 多值 `；` |
| `不适合：` | cognition.not_for[] | 条件必(§4 规则 11) | 多值 `；`；支持结构化写法,见 §4 规则 7 |
| `差异化：`/`为什么选它：` | cognition.differentiators[] | 选 | 多值 `；`；只写本商品有依据的特点,不跟别家比,见 §4 规则 10 |
| `契合理由：` | cognition.fit_reasons[{for,reason}] | 选 | `人群或场景(理由)` 或 `人群或场景<-理由`，多条换行 |

> **v4 已下线 `类目：`/`商品分类：`**:类目统一由平台类目分类器判定,知识卡不再填写;`定位` 写清商品本体即可帮分类器判准。解析器暂保留这两个别名,只为兼容存量知识卡,新卡不要再写。

## 2.1 意图/推荐增强字段·作用说明(准确率导向)

> 目标不是省 LLM，而是**推荐更准**。准确率的三个病根：①召回错(该出的没出/误召回) ②排序错(相似品里选错) ③理由错(推对了但没戳中需求)。下面 5 个字段分别对症，是 2026-08-20 为提升"意图理解准 + 推荐准"新增。

| 字段 | 治哪个病根 | 作用(为什么加) | 消费方 |
|---|---|---|---|
| **needs 需求/痛点** | ①召回 | 导购 query 是**需求语言**("加班没空吃饭""想犒劳自己")，商品默认是**属性语言**，两者对不上就召回错。商品自带需求词 → 与用户表达同频，**进 embed_text 直接改善意图召回对齐**。最大杠杆。 | 向量召回 + advisor |
| **query_phrases 用户会怎么问** | ①召回 | 补**词汇鸿沟**:用户口语提问/俗称("有没有辣的""番茄面""管饱的")与商品名/卖点用词不一致。显式存"用户视角说法"，进召回让语义/关键词都能咬上。 | 向量召回 + 关键词召回 |
| **not_for 不适合/排除** | ①召回(负向) | **负向匹配信号**:"不适合的人/场景"(如 对鸡蛋过敏、婴幼儿)。用户命中排除条件时**直接砍掉**，避免"先误推、再让 LLM 圆场"。准确率里"不该出的别出"这一半靠它。**≠ 禁用表达**(那是合规不能说的话，这是不匹配的对象)。 | 排序过滤 + advisor |
| **differentiators 差异化点** | ②排序 | 召回回来一堆相似品，凭什么选中该推的?**"这款自己有什么特点"**(如"面里加了真鸡蛋",须有依据,不写"唯一"等比较说法)。给 LLM 生成**有说服力**的理由、辅助排序区分，否则推荐千篇一律。 | advisor 生成 + 排序 |
| **fit_reason 契合理由** | ③理由 | 推对商品后，理由要按**不同意图**说不同话。`人群或场景(理由)`(如 `加班宵夜(开水冲泡3分钟就能吃)`)，让 advisor 生成**个性化**推荐语，而非复读卖点。 | advisor 生成 |

**进不进向量(embed_text)的边界**:
- **进** ✅:`needs`、`query_phrases` —— 属"意图对齐"，进向量提升召回。
- **不进** ❌:`not_for`(负向，进了会污染语义)、`differentiators`(营销倾向，保持向量只讲可核实事实/能力)、`fit_reasons`(生成侧素材)。

## 2.2 扩展区标签(v4 新增·原文暂存,解析待上线)

> 这些标签**现在不被解析器解析**,原文保存在 `ai_product_intro`;等解析器与落库改造上线后统一补刷。运营现在填,数据先到位,上线即可用。全部**选填**,运营没给就不写。

| 标签 | 值格式 | 示例 | 上线后的用处 |
|---|---|---|---|
| `型号：` | 单值 | `型号：AF-550` | 用户按型号指代("X406 怎么样")能对上商品;区分同款不同代 |
| `规格参数：` | 每行一条 `参数名=值单位(来源)`,参数名自由写;来源取 §4 规则 1 的固定列表 | `容量=5.5升(铭牌)` | 规格筛选("5 升以上")、多款参数对比、追问选项、有数字依据的推荐理由 |
| `适用年龄：` | `下限-上限` 或 `X以上`/`X以下`,单位 `月`/`岁` | `0-6月`、`3岁以上` | 年龄硬过滤(不给新生儿推 L 码) |
| `资质：` | 每行一条 `资质类型=编号(有效期至YYYY-MM-DD)`,有效期可省 | `保健食品注册号=国食健注G20200001(有效期至2030-01-01)` | 风险品类按资质决定是否推荐,见 §5.1 |
| `卖点依据：` | 多值 `；`,每条 `卖点=规格参数名或关键事实` | `高钙=钙含量；大容量=容量` | 有依据的卖点才可当推荐理由,防 AI 夸大 |

**扩展区规则**:
1. `规格参数` 只写**客观可量化或可枚举**的参数(容量、功率、净含量、段位、材质、口味);主观评价("口感好")不写。数值和单位写在一起,同一参数只写一种单位。
2. `规格参数` 只写运营给出的值,**不替商家换算或估计**;来源为 `商家口述` 的,末尾加 `[推断]`。
3. 不写 SKU 信息(颜色/尺码/套餐组合的价格与库存),那由商城 SKU 数据提供。
4. `卖点依据` 等号左边必须是 `核心卖点` 里出现过的卖点,右边必须是本卡 `规格参数` 的参数名或某条 `关键事实`;对不上的不写。
5. 扩展区的值里同样不要出现裸标签名+冒号。

## 3. 判定阈值(命中才走规则解析)

> 行首识别到的已知标签数 **N ≥ 3**，且至少命中 `核心卖点` 或 `关键事实(商品介绍)` 之一且非空。扩展区标签不计入 N。
> 不满足 → 系统降级 LLM(Python)或跳过(Java 直落路)。

## 4. 关键规则

1. **卖点 vs 事实分离**:
   - 核心卖点 = 营销主张(高钙高蛋白 / 便携),打动人即可。
   - 关键事实 = 客观可核实(每100ml含钙约120mg / 机身厚16mm)。
   - 事实末尾标 `(来源)`,来源**只能从固定列表选**(v4.3 起 9 项):`包装`、`配料表`、`营养成分表`、`铭牌`、`说明书`、`检测报告`、`详情页`、`标题`、`商家口述`。
   - `详情页`/`标题` = 商家在商品页公开发布、买家可见的文字,可作 `verified=true`;但**宣传性形容词不写进 `关键事实`**,只原样留在 `核心卖点`(见规则 10「强度」)。`商家口述`(口头/聊天/私下告知)仍须加 `[推断]`。
   - 来源为 `商家口述`,或运营明确说是推断的,末尾再加 `[推断]`,如 `五谷喂养(商家口述)[推断]`(→ verified=false,不作推荐硬证据、不进向量)。
   - **来源优先级(v4.3)**:`铭牌 > 说明书 > 检测报告 > 营养成分表 > 配料表 > 包装 > 详情页 > 标题 > 商家口述`。同一事实有多个来源时取**优先级最高**的那个;资料里已有高优先级来源(如说明书、铭牌),**不得降级写标题、不得因别处没提就删掉**。已核实的数值被降级或丢失,是当前"关键事实冲突"的主要成因。
   - **参数不遗漏**:资料给出的可量化核心参数(功率、容量、容量/额定容量、尺寸、重量、频响、续航、充电时间等)尽量**全部**写进 `规格参数`;不要只挑 3 项"精简",除非触发 §4 规则 16 的长度上限。
   - **数值冲突**:同一事实在两处给出不同数值且无法判断哪个对(如检测项数一处 116 项、一处 424 项),**不写具体数字**,改写定性事实(如 `通过SGS兽残检测(检测报告)`);宁少写,不写错。
2. **能力**:`能力名(证据1；证据2)` 或 `能力名<-证据1；证据2`,须由卖点/事实支撑,如 `营养早餐(高钙高蛋白)`。证据可省(只写能力名)。多条换行。
   - 括号写法更便于运营输入,与 `<-` 等价并存;中英文括号均可。契合理由同理:`场景(理由)` 或 `场景<-理由`。
3. **值内不要出现裸标签名+冒号**(如卖点内容里写 `事实：`),会干扰行首解析。
4. **适用人群 / 适用场景:有依据才写,"也适合"不写**。写错比不写代价大:错的人群会被导购当事实说,将来做过滤还会筛错;没写 = 不限定,导购会按商品事实现场判断。
   - **人群**满足任一才写:① 资料原文写了(包装/详情/说明书/运营原话,如"儿童""孕妇""老人");② 规格决定了只给这类人用(NB码纸尿裤→新生儿;孕妇装→孕妇;1段奶粉→0-6月婴儿;保健食品标签的"适宜人群")。
   - **人群不写**:只是"也能用"的(牛奶≠儿童,鸡蛋≠中老年);人人都能用的通用商品整行不写,**不要写"成人"凑数**;不从品类、价格、包装风格推人群。
   - 自查一问:"买家不是这类人,这商品就不能用了吗?"——照样能用,就不写。
   - **场景**只写资料写到的,或商品的直接用途(雨伞→雨天;保温杯→通勤);`送礼`/`犒劳自己`/`宵夜` 这类营销联想,资料没写不写(场景进向量,乱写会扩大误召回)。
   - 下列参考词只用来**统一叫法,不是默认值**:人群 儿童 / 青少年 / 中老年 / 孕妇 / 哺乳期 / 健身增肌 / 减脂;场景 早餐 / 办公室 / 运动后 / 出差。
   - `定位` 里的"适合谁/什么场景"同此口径。
   - **功效**(仅保健营养类)参考:助睡眠 / 补钙 / 膳食纤维补充 等(合规红线见 §5)。
5. **定位(skill 层面必填)**:一句话说清"这是什么东西",用买家的叫法。分类器判类目、向量召回、导购介绍商品都用它。
   - 写法:`<1-2 个关键特征> + <商品本体通名>，<适合谁/什么场景>(可选,口径同规则 4)`。
   - **必须含商品本体通名**(空气炸锅 / 纸尿裤 / 挂面 / 手机壳);只有品牌、系列名或营销词的不合格。
   - **本体要写对**:原料、产地、口味、工艺不改变本体。鸡蛋挂面的本体是挂面,苹果手机硅胶壳的本体是手机壳,牛奶味饼干的本体是饼干。
   - **特征必须是事实**,最好在关键事实或规格参数里有依据;不写"爆款""品质之选""最好"。
   - **只写一件商品**;套装/礼盒写清主体,如 `坚果礼盒(6种坚果混装)`。
   - **30 字以内**,不写品牌和型号(有单独标签)。
   - 运营给的信息说不清本体时,先追问,不出卡。

   | 不合格 | 问题 | 合格 |
   |---|---|---|
   | 厨房好帮手 | 没有本体 | 5.5升可视空气炸锅，适合3-4口之家 |
   | 高钙营养早餐奶 | 本体"奶"太含糊 | 高钙水牛纯牛奶，适合早餐和儿童 |
   | 散养土鸡蛋挂面 | 本体易被误读成鸡蛋 | 加鸡蛋的手工挂面，煮3分钟即食 |
   | 苹果15专用 | 主机还是配件分不清 | iPhone 15 硅胶手机壳，防摔 |
   | 宝宝夜间好伴侣 | 没有本体 | 新生儿NB码纸尿裤，夜用加厚吸收 |

6. **功效只限保健营养类**:普通商品(含普通食品、乳品)写的"功效"一律改写进 `核心卖点`(如普通牛奶的 `高钙` 是卖点不是功效),不写 `功效：` 标签。
7. **不适合·结构化写法**:能归类的按下面三种写,归不进的照旧写大白话,多值 `；` 混写即可。
   - `过敏原=<过敏原>`,如 `过敏原=乳糖`、`过敏原=花生`;
   - `人群=<人群>`,如 `人群=孕妇`、`人群=婴幼儿`;
   - `年龄=X岁以下` / `年龄=X月以下`,如 `年龄=3岁以下`(不用 `<` 号:商家后台编辑器或 XSS 过滤可能把它转义)。
   - 示例:`不适合：过敏原=乳糖；人群=孕妇；不喜甜食者`。
8. **没有就不写,不写占位值**:基础区和扩展区一样,运营没给的标签**整行不写**。
   - 禁止把 `待确认`/`待补充`/`未知`/`不详`/`暂无`/`无`/`默认`/`其他`/`-`/`/` 这类占位写成值——解析器会把它当真实值落库(如品牌名变成"待确认")。
   - 原始资料里的占位也不能照抄:商城规格值是 `默认`、品牌栏是空或 `无`,视同没给。
   - 一个标签里部分值是占位的,只删占位,保留真实值。
9. **无法追问时(批量 / 表格导入 / 要求直接出结果)**:不能把"问运营"变成写进卡里的值。
   - 选填信息缺失或拿不准 → 整行不写;拿不准是卖点还是事实、来源不明的事实 → 不写。
   - 必填(定位/核心卖点/关键事实)缺失,或说不清商品本体 → **不出卡**,该商品只输出下面这段说明(不用标签格式):
     ```
     资料不足，暂不生成知识卡（商品：<商品名称>）
     缺少：<字段>、<字段>
     请补充：<具体要什么原始资料，如 包装上的配料表、营养成分表、规格参数>
     「AI 商品简介」请保持原样，不要粘贴本段。
     ```
     这段是给运营的提示,不是知识卡:误贴进 `ai_product_intro` 不会生成新卡,但该商品的旧卡会继续生效。
10. **依据链:换说法可以,加信息不行**。`需求`/`用户会问`/`推荐关键词`/`能力`/`差异化`/`契合理由`/`允许表达`/`使用建议` 是把资料翻译成买家的话,每句都要能对回本卡的某条卖点、事实或规格参数,且不比原文说得多。逐句过三问:
    - **本体**:买家这么问,这商品是正确答案吗?只写商品本体或它真实所属的上级类;相邻/错误品类不写(红薯→粗粮、薯类 ✅,红薯→水果 ❌;苹果不写成冬枣)。平台分类与商品名矛盾时以商品名为准。
    - **强度**:这句比原文更强吗?不加条件(湿水时)、不加程度(完全/不会/一定)、不加结果(安全/解腻/助消化)。保证、安全、效果类说法必须资料或检测报告原文就有;商家标题的宣传词只原样留在 `核心卖点`(标题"防滑"→卖点 `防滑` ✅,能力 `湿水也不易滑` ❌)。
    - **对比**:拿谁比的、依据在哪?skill 没有竞品数据,`差异化` 只写本商品自己的特点(`生水牛乳为原料`),不写 `高于普通…`/`唯一`/`更…`,除非资料原文这么写。
    - `使用建议` 只写资料给的用法,不自己补吃法(不写 `洗净即食`,生食可能有安全问题)。
    - 对不上依据的句子删掉;删完这一行空了就整行不写。

11. **强制触发字段:命中就得有(v4.3)**。同一份资料换个人、换个批次产出应该一致,靠的就是这张表——左列命中,右列字段**必须出现**,不因"资料没强调"而省略。缺依据时该字段不写值,但先确认是否真无依据(见下方"安全提示例外")。

    | 命中条件(任一) | 必须出现的字段 |
    |---|---|
    | 任何实体商品 | `定位`、`核心卖点`、`关键事实`;资料有量化参数时必写 `规格参数` |
    | 食品/饮料/农产品/生鲜 | `禁用表达`、`允许表达`;配料含过敏原则 `不适合：过敏原=X` |
    | 含酒精(白酒/啤酒/果酒) | `不适合：人群=未成年人；人群=孕妇；人群=驾车人员`、禁用表达(养生保健/治疗疾病) |
    | 含咖啡因(咖啡/茶/功能饮料)、药食同源(人参/肉苁蓉/灵芝/黄芪/枸杞等) | `不适合：人群=孕妇；人群=哺乳期；人群=儿童`;资料给食用量上限则写 `使用建议` |
    | 保健食品 | `资质`、`功效`、`不适合`;`允许表达` 须含「保健食品不是药物，不能代替药物治疗疾病」 |
    | 母婴/儿童/玩具 | `适用年龄`、禁用表达(长高/助力发育类)、`不适合：年龄=X岁以下`(资料有明确的才写) |
    | 电器/数码/充电宝/灯具 | `规格参数`(铭牌优先)、禁用表达(绝对安全/永不损坏/100%防水) |
    | 洗护/化妆品/纸品 | `禁用表达`、`允许表达` |
    | 名称或详情含 送/赠/套装/组合/礼盒/共N件 | `关键事实` 写清套装构成与赠品;单品写清"N件/箱" |
    | 出现检测/认证/专利/机构背书(SGS、NSF、ISO、ROHS、红点、农科院、发明专利号) | `关键事实` 写清机构+项目+来源;无来源不得进 `核心卖点` |
    | 住宿/餐饮/到店服务 | `规格参数` 或 `关键事实`(房型/床型/面积/份量/服务项)、`不适合`(可吸烟房→烟味敏感者、携带宠物者) |
    | 需资质品类(§5.1) | `资质`(运营给了才写),并按 §5.1 提醒 |

    - **安全提示例外**:§4 规则 4 说"人群不从品类推",但**过敏原与法定禁忌可以推**——配料表含牛奶/小麦/坚果 → `过敏原=牛奶/小麦/坚果`;含酒精 → 未成年人/孕妇/驾车人员;含人参、肉苁蓉等 → 孕妇/哺乳期/儿童。这属安全提示,不算编造。
    - 反之,没有法定禁忌依据的"儿童/中老年/成人"仍按规则 4 不写。

12. **合规闭环自检(写完必扫一遍,v4.3)**。"无依据卖点入库""禁用词反向入库"是当前最严重的合规事故,靠输出前一次反向扫描兜住:
    - 把 `禁用表达` 里每一项,与本卡所有**正向字段**(定位/核心卖点/关键事实/能力/使用感受/使用建议/需求/用户会问/推荐关键词/差异化/契合理由/允许表达)逐条做**包含式匹配**,命中就删或改成合规说法。
    - **严禁出现"禁用表达里有、正向字段里也有"**——例如一边在 `禁用表达` 写「小分子团水」,一边在 `核心卖点` 写「小分子团水」,这是最严重的合规倒退。
    - 功效类词(治疗/治愈/降三高/减肥/增强免疫/排毒/壮阳/养生)、绝对化词(最/第一/国家级/唯一/100%/绝对/永不)、机构背书(农科院/诺贝尔/专利) → 没有检测报告或包装原文依据,**一律不得进 `核心卖点`、`关键事实`、`能力`、`差异化`、`契合理由`**;有依据的,依据要同时写进 `关键事实`。
    - `允许表达` 必须是能直接对外说的合规句,不能又写成禁用词或空话。

13. **推荐关键词口径(v4.3)**。关键词直接决定召回,两版不一致会让搜索分叉:
    1. 必含**商品本体通名**,与 `定位` 里的本体一致;
    2. 资料有品牌 → 必含品牌词;
    3. 套装/组合/礼盒 → 必含「套装」或「礼盒」,且与 `商品名称` 用词一致(不能一处"套装"、一处不写);
    4. 只从 `商品名称`/`定位`/`核心卖点`/`关键事实` 取词;`[推断]` 事实里的词不得单独作关键词;
    5. 排序:本体词 → 品牌词 → 场景/人群词 → 属性词;3-8 个,同义词堆叠只留更通用的一条(如"咖啡；黑咖啡"留一个主词);
    6. 不得写无依据品类词(同规则 10「本体」)。

14. **名称/品牌/套装口径(v4.3)**。同一商品的名称与品牌不一致,会让导购"认错商品":
    - `商品名称` 取资料里**最完整的正式名**(包装/标题),去掉促销语、运费/佣金说明、面值、客服电话、括号里的赠品说明;
    - 资料(标题/包装/详情)出现品牌 → **必须**写 `品牌：`;名称内含品牌时与 `品牌：` 保持一致;品牌只是推断 → 不写;
    - 赠品写进 `关键事实`(如 `附赠化橘红1盒(标题)`),**不进** `定位`/`核心卖点`;本体本身就是套装的,`定位` 写清「礼盒/套装(含 A+B)」;
    - 商品名与平台类目矛盾时以商品名为准(同规则 10)。

15. **冲突与确定性(v4.3)**。批量场景下没法追问,必须落到确定规则上:
    - 同一事实多来源冲突 → 按规则 1 的**来源优先级**取值;仍判断不了 → 不写具体数值,写定性事实;
    - 拿不准一律取**更严/更少**的一侧:合规取更严的禁用表达,事实取更保守表述,人群取更小范围;
    - 同一商品在**同一批次内必须同口径**:资料写得少不构成"反转结论"的理由(见 §5.2 同批一致性)。

16. **超长裁剪顺序(v4.3)**。`ai_product_intro` 有长度上限(生产库 `VARCHAR(2000)`)。超长时按此顺序删,删到够为止:
    `使用感受` → `常见问题` → `差异化` → `契合理由`(留 1 条) → `需求`/`用户会问`(各留 2 条) → `推荐关键词`(留 3 个)。
    **绝对不删**:`定位`、`核心卖点`、`关键事实`、`规格参数`、`资质`、`禁用表达`、`允许表达`、`不适合`。合规与事实字段优先于文案字段。

## 5. 合规红线(违反必须拒绝写入,改成合规说法)

- 任何商品:不得用 `最 / 第一 / 国家级` 等绝对化用语当卖点。
- 食品/普通商品:不得宣称 `治疗 / 治愈 / 养生治病 / 更营养一定`。
- 保健营养类:不得宣称 `增强免疫 / 长高 / 治愈疾病` 及任何医疗用语;`功效` 只能写保健/改善方向。
- 儿童相关食品:不得宣称 `长高 / 助力成长发育 / 助力长身体` 等生长发育类功能。
- 违规词写进 `禁用表达`,合规推荐说法写进 `允许表达`。

## 5.1 内容风险判定(v4 新增)

> 不依赖类目,只看运营提供的内容。类目判错时,这是一道兜底;将来系统按"类目风险与内容风险取更严"定最终风险等级。

| 命中内容(商品名称/定位/卖点/事实/功效等任一处) | 风险 | skill 处理 |
|---|---|---|
| 药品、OTC、处方药、中西成药;烟草、香烟、电子烟、烟弹 | **禁售** | **拒绝录入**,告知运营该类商品不进入 AI 导购 |
| 保健食品、蓝帽、国食健注、食健备 | 需资质 | 提醒补 `资质：保健食品注册号/备案号`;不补也出卡 |
| 特殊医学用途配方食品、特医 | 需资质 | 提醒补 `资质：特医食品注册号`;不补也出卡 |
| 婴幼儿配方奶粉/乳粉 | 需资质 | 提醒补 `资质：婴幼儿配方乳粉产品配方注册号`;不补也出卡 |
| 化妆品(护肤/彩妆/洗护中标称化妆品的)、特殊化妆品(防晒/染发/烫发/祛斑美白/防脱) | 需资质 | 提醒补 `资质：化妆品备案号/注册证号`;不补也出卡 |
| 医疗器械、械字号、隐形眼镜 | 需资质 | 提醒补 `资质：医疗器械注册证号/备案号`;不补也出卡 |
| 农药、杀虫剂(农用) | 需资质 | 提醒补 `资质：农药登记证号`;不补也出卡 |

- 资质编号只写运营提供的,**不编造、不补全**;编号格式看不懂的原样保留。
- 上表的资质类型名称供 skill 提示用,具体以监管部门公布的名称为准【待补充:各类资质的官方查询地址,需业务/法务确认】。

## 5.2 准入判定:先判能不能出卡(v4.3 新增)

> 当前最严重的问题是**出卡结论冲突**(同一商品一份出卡、一份判"资料不足不出卡",导购推送结果相反)。根因是"资料不足"没有客观门槛,全靠临场判断。按商品**形态**给判定,命中即执行,**不做自由裁量**。

| 商品形态 | 判定 | 依据 |
|---|---|---|
| 药品/OTC/处方药/烟草/电子烟 | **拒绝录入** | §5.1,不进入 AI 导购 |
| 非实物占位:积分专属、身份激活、客服专线、纯跳转链接、无商品名的"专属产品" | **不出卡** | 无商品本体,写不出 `定位` 的本体通名 |
| 虚拟卡券/权益:购物卡、兑换券、提货券、会员卡 | **不出卡** | 认知卡服务于实物商品的推荐;卡券信息由商品主数据提供,不建认知卡 |
| 纯服务/到店服务(理发、维修、家政、法律咨询) | 有**明确服务项**且可核实(如"房车上门剪发")→ **可出卡**;只有"权益/套餐"无服务范围 → **不出卡** | 服务项写进 `规格参数` 或 `关键事实` |
| 住宿(房型) | 有床型/面积/窗/吸烟等可核实项 → **可出卡** | 缺失项不写,口述来源标 `[推断]` |
| 餐饮(餐品/套餐) | 有菜品/份量/价格等可核实内容 → **可出卡**;**只有"以当日供应为准/以实际为准" → 不出卡** | 不可核实的表述不能当唯一事实 |
| 实体商品 | **可出卡** | 必填齐即可 |

- **不出卡 ≠ 不输出**:必须按 §4 规则 9 输出那段说明(缺什么、补什么、不要粘贴),**绝不留空**。留空 = 该商品旧卡继续生效,是最危险的状态。
- **同批一致性**:同一商品在同一批数据里只允许一个结论。资料写得少不是反转理由——少就按"不出卡"处理,不能一会儿出卡、一会儿不出卡。
- **判定顺序(必须按此顺序,前一步不通过不进入下一步)**:
  `准入(§5.2) → 内容风险(§5.1) → 必填齐全(§4 规则 5/9) → 触发字段(§4 规则 11) → 合规闭环(§4 规则 12) → 输出自检`

## 5.3 品类基线禁用表达(v4.3 新增)

> 合规表达不一致(一份有、一份缺)是命中面最广的问题。解法是**给基线**:命中品类就自动补,资料里额外有的继续加、不删。两版都按同一基线补,口径自然一致。
> 基线是**下限**,不是全集。

| 品类 | 基线禁用表达 |
|---|---|
| 通用(所有商品) | 最好；第一；国家级；唯一；100%；绝对；性价比之王；全网最低 |
| 食品/饮料/农产品/生鲜 | 治疗；治愈；降血糖；降血压；降血脂；减肥；增强免疫力；防癌抗癌；排毒；养生治病；无副作用；绝对安全 |
| 保健食品 | 治疗疾病；代替药物；快速救心；急救心脏；1-2分钟起效；根治；增强免疫(允许表达固定写：保健食品不是药物，不能代替药物治疗疾病) |
| 酒类 | 养生保健；壮阳；有益健康；治疗疾病；纯粮不上头 |
| 洗护/化妆品/纸品 | 绝对不伤手；100%除菌；无任何化学添加；永久有效；根治；医疗级 |
| 家电/数码/充电宝 | 绝对安全；永不损坏；100%防水；永久续航 |
| 母婴/儿童 | 助力长高；促进发育；绝对安全；替代母乳 |
| 涉功效暗示的水/茶/食材 | 小分子团水；负电位；负氧离子；远红外；碱性体质；抗癌 |

- 配套写一句 `允许表达`,是能直接对外说的合规句(如 `一款含岩藻多糖的康普茶风味营养素饮料`、`无磷配方，机洗手洗均可`),不要写成空话或又把禁用词塞回去。
- 与 §5.1 资质提醒一起用:风险品类出卡前,先补 `禁用表达`+`允许表达`+`不适合`,形成**合规三段式**。


## 6. 落库去向(供理解,商家无需关心)

- 结构化结果落 `t_product_attr`,2026-09-02 起**每类字段一个独立列**(不再堆 `cognition`/`guardrails` 一个大 JSON):
  定位/能力/事实/qa/需求/用户会问/不适合/差异化/契合理由/使用建议/**场景/功效/人群/使用感受** 各进各列;
  合规边界拆成 `allowed_expr`/`forbidden_expr` 两列。老数据的 `cognition`/`guardrails` 保留供回落读。
- 向量 `embed_text` 取"意图/能力/事实/场景/功效"侧(定位+summary+能力+**需求+用户说法+场景+功效**+类目+verified 事实),
  **排除卖点(is_claim)/推断/使用感受/不适合/差异化/契合理由/使用建议/人群/guardrails**;人群计划走硬过滤(检索侧尚未实现)。
- 原文 `ai_product_intro` 保留在 `t_product_detail` 溯源。**扩展区(§2.2)目前只存在原文里**,解析器上线后从原文补刷入库。
- ⚠️ 生产库 `ai_product_intro` 目前是 `VARCHAR(2000)`,超长会写库失败;知识卡请尽量精简,待该列扩容为 `TEXT`。

## 7. 填哪些信息,商品更容易被搜到、被推荐

> 买家在智能导购里常用大白话找东西("有没有适合老人补钙的""加班能对付一口的")。你把下面这些信息填清楚,系统就更容易把你的商品匹配给对的买家,导购也更会帮你推荐。**想让商品更好卖,优先填「定位」「需求」和「用户会问」。**

**这些最能帮商品"被买家搜到"(优先填)**

| 你填的信息 | 为什么有用 |
|---|---|
| **定位** | 一句话说清"这是什么东西、给谁用",系统靠它把商品归到对的品类。**必填。** |
| **需求 / 解决问题** | 买家常按"要解决什么问题"来搜("没时间做饭""想犒劳自己");写清商品解决啥问题,就和买家的说法对上了。**最管用,优先填。** |
| **用户会问 / 搜索说法** | 买家嘴里的叫法常和商品名对不上("有没有辣的""管饱的""番茄面");把买家可能怎么问写进来,更容易被搜到。 |
| **关键事实(注明来源)** | 成分、规格、含量这些实打实的信息,是买家判断和搜索的依据。(商家口头说的标一下,系统不当真) |
| **能力** | 商品"能帮买家做到什么"(开袋即饮、方便携带)。 |
| **适用人群 / 场景 / 功效** | 帮买家按"给老人 / 宵夜 / 助眠"这类需求找到你。**资料里写了才填**,人人都能用的商品不填人群——填错会推给不对的人。 |
| **品牌** | 归到对的品牌下,别被搜错。 |

**这些让智能导购"更会推、更会说"(不直接帮被搜到,但同样重要)**

| 你填的信息 | 为什么有用 |
|---|---|
| **核心卖点** | 打动买家的主张,用来展示和介绍。 |
| **差异化 / 为什么选它** | 你这款自己的特点(要有依据,别写"最好""唯一""比别家强"),导购据此帮你说服买家。 |
| **契合理由** | 针对不同买家说不同的推荐理由,更打动人。 |
| **不适合** | 说明"哪些人 / 场景不合适",避免推给不对的人、招差评。 |
| **常见问题** | 买家常问的问答,导购能直接答上。 |
| **禁用 / 允许表达** | 合规红线:哪些话不能说、该换成什么说法。 |

**这些让导购将来能"按参数挑、按参数比"(扩展区,现在先填好,系统升级后自动生效)**

| 你填的信息 | 为什么有用 |
|---|---|
| **规格参数** | 买家说"5 升以上""噪音小一点"时能按参数挑出来,也能把几款放一起比。 |
| **型号** | 买家直接报型号问时能对上。 |
| **适用年龄** | 母婴、儿童商品不会推给年龄不合适的孩子。 |
| **资质** | 保健食品、化妆品等需要资质的商品,有资质才放心推荐。 |
| **卖点依据** | 卖点有参数撑腰,导购才敢拿它当推荐理由。 |

**一句话**:必须填「定位」「核心卖点」和「关键事实」;想让商品更容易被搜到、卖得更好,再按 **需求 → 用户会问 → 能力 → 差异化 / 契合理由 → 人群 / 场景 / 功效 → 常见问题** 补;有参数、型号、年龄要求或资质的,写在商品名称下面的扩展区。
