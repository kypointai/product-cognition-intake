## v4.3(2026-11-25)· 一致性专项:准入门禁 + 触发式必填 + 合规闭环

- 起因:1505 批量出卡与"回填"版本对同一批商品做了 A/B 对比,30 条明细里 7 类问题均指向**同一根因——该有判定门槛的地方靠临场发挥**,导致同一份资料产出两套结论。

| 问题类型(命中数) | 根因 | v4.3 改法 |
|---|---|---|
| **出卡结论冲突**(6 首要,致命) | "资料不足"无客观门槛,非实物/卡券/服务/餐饮全凭感觉 | 新增 **§5.2 准入判定**:按商品形态给 7 类判定(拒绝/不出卡/可出卡)+ 明确"不出卡≠不输出,绝不空白"+ 同批一致性 + 判定顺序 |
| **合规表达不一致**(11 首要 / 15 命中) | `禁用表达`/`允许表达` 是选填,无基线 | 新增 **§5.3 品类基线禁用表达**(通用/食品/保健/酒/洗护/家电/母婴/涉功效水茶),命中品类即补齐;`规范.md` §4 规则 11 把"禁用表达+允许表达+不适合"列为触发式必填 |
| **风险提示缺失**(5 首要 / 8 命中) | `不适合` 无触发条件 | §4 规则 11 触发清单:含酒精→未成年人/孕妇/驾车人员;含咖啡因/药食同源→孕妇/哺乳期/儿童;可吸烟房→烟味敏感者。并补"**安全提示例外**":过敏原与法定禁忌可从配料/成分推定,不算编造人群 |
| **关键事实冲突**(3 首要 / 13 命中) | 无来源优先级,说明书/铭牌参数被降级成"标题"或漏写 | §4 规则 1 新增**来源优先级**(铭牌>说明书>检测报告>营养成分表>配料表>包装>标题>口述)+"不得降级、参数不遗漏"+"数值冲突不写数字改写定性" |
| **无依据卖点入库**(1 首要,致命倒退) | 写完没有反向检查,禁用词又写回卖点 | §4 规则 12 **合规闭环自检**:禁用表达逐条与所有正向字段做包含式匹配,严禁"禁用表达里有、卖点里也有";功效词/绝对化/机构背书无依据不得进卖点 |
| **关键词口径不一**(2 首要 / 19 命中) | 关键词无生成口径 | §4 规则 13:必含本体通名、品牌词、套装词(与商品名一致)、只取可核实词、固定排序、同义不堆叠 |
| **表述细节差异**(2 首要 / 7 命中) | 商品名/品牌/赠品随人而变 | §4 规则 14:名称取最完整正式名并去促销语/运费/面值;有品牌必写 `品牌：`;赠品进关键事实不进定位 |
| 卡片超长写库失败风险 | 触发字段变多后更容易超 2000 字符 | §4 规则 16 **超长裁剪顺序**:先删使用感受/常见问题/差异化/契合理由/需求,绝不删定位/卖点/事实/规格/合规字段 |

- 同步 `system-prompt.md`:新增「**第 0 步:准入判定**」(置于硬规则之前,提升执行优先级)+ 硬规则 1 补来源优先级 + 新增硬规则 **16 触发式必填、17 合规闭环(含基线词库)、18 关键词与命名口径、19 确定性**,并在「输出前自查」加 4 条检查。
- 同步 `SKILL.md`:职责边界写入准入与"不出卡不留空";交互流程增 **第 0 步**,第 5/6 步拆出"基线补全"与"合规闭环"。
- 同步 `examples.md`:新增 **例6 酒类(合规三段式)、例7 住宿服务(可出卡+风险提示)**、**不出卡样例**(非实物/卡券/餐饮)、反例 3 组(**合规闭环失败 / 来源降级与漏参 / 关键词与名称口径**)。
- **事实来源由 7 项扩为 9 项**(新增 `详情页`、`标题`)。原因:回填批次的数据源就是标题/详情页,原列表里没有对应来源,模型只能硬写成「包装」(失真)或「商家口述+[推断]」(被降级、不进向量)——这本身是"关键事实冲突"的隐性成因。`详情页`/`标题` 是商家公开发布、买家可见的文字,可作 `verified=true`;`商家口述`(口头/私下)仍须 `[推断]`。
  - 代码侧影响:**无需改动**。Java `IntroSoftSpecParser.SOURCE_RE` 与 Python `_SOURCE_RE` 只抓括号内容、不校验白名单;`source` 字段全链路只存不判,只有 `verified` 参与 embed_text 与生成素材筛选(已核 `ProductAttrExtractServiceImpl:775`、`copywriting.py:74`、`consult.py:350`)。
- **顺带修复(代码,2026-11-25)**:Python `app/retrieval/intro_parser.py` 缺 `使用感受`(口感/肤感/手感/气味)、`使用建议`(食用建议)别名,而 Java 一直支持。缺别名的后果是这些行被并进上一条标签(多为 `关键事实`),变成 `{"claim":"使用建议：冷藏保存","source":null,"verified":true}` 并进 summary/向量——静默污染,正好对应本次要治的"无依据内容入库"。已补别名,并把 `sensory`/`usage_tips`/`scenarios`/`efficacy`/`audience` 补进 `attributes`(键名对齐 Java `distributeKnowledgeColumns`)。回归:`tests/fixes/intro_parser_sensory_usage/`。
- **纯提示词改动**:未新增/改名任何标签,阈值 N≥3 不变,**解析器无需改动**。


## v4.2(2026-11-22)· 人群/场景有依据才写 + 依据链
- 起因:首批 300 条样本 250 张含"成人";参考词表被当成默认值,示例也在无依据填人群。

- §6 更正:人群硬过滤检索侧尚未实现,改为"计划"。
- 同步 `system-prompt.md`(硬规则 4、模板、示例)、`SKILL.md`、`examples.md`(例1 删"成人"、例2 删人群行、补依据说明与反例)。
- 依据链(`规范.md` §4 规则 10、`system-prompt.md` 硬规则 15):需求/用户会问/关键词/能力/差异化/契合理由/允许表达/使用建议"换说法可以,加信息不行",逐句过本体、强度、对比三问。起因:红薯被扩成"当季水果"、标题"防滑"被写成"湿水也不易滑"、酵素被加"佐餐解腻"。

## v4(2026-11-16)· 扩展区 + 定位必填 + 风险判定,下线类目
- **先改 skill、代码后续排期**:运营先按 v4 补数据,解析器与落库改造另行排期。
- 新增**扩展区**标签(全部选填):`型号：`、`规格参数：`(每行 `参数名=值单位(来源)`,参数名自由写)、`适用年龄：`、`资质：`(`资质类型=编号(有效期至…)`)、`卖点依据：`(`卖点=参数名或事实`)。
  - 位置固定在 `商品名称：` 之后、第一个基础区标签之前:现有解析器把这段当商品名称边界忽略,原文留在 `ai_product_intro`;放到基础区后面会被并进上一个标签(已用 Python `intro_parser` 实测,Java `IntroSoftSpecParser.detect` 逻辑相同)。
  - 扩展区不计入阈值 N;解析器上线后从原文补刷。
- `定位：` 改为 skill 层面必填,须含商品本体通名(写法与对照表见 `规范.md` §4 规则 5);解析器阈值不变。
- `关键事实` 来源改为固定列表(包装/配料表/营养成分表/铭牌/说明书/检测报告/商家口述),`商家口述` 自动标 `[推断]`。
- `不适合：` 支持结构化写法 `过敏原=X；人群=X；年龄=X岁以下`,与大白话混写兼容(年龄不用 `<` 号,避免被商家后台编辑器或 XSS 过滤转义)。
- `功效：` 只限保健营养类,普通商品的"功效"改写进核心卖点。
- 新增内容风险判定(`规范.md` §5.1):药品/烟草/电子烟拒绝录入;保健食品/特医/婴配/化妆品/医疗器械/农药提醒补资质,不补也出卡。
- 合规红线补充儿童食品生长发育类宣称(长高/助力成长发育/助力长身体)。
- **下线 `类目：`/`商品分类：`**:类目由平台类目分类器判定。解析器暂保留别名以兼容存量卡。影响:新卡解析后 `ai_category` 为空(Java `writeBackToProduct` 为空不写),ES 的 `ai_category` 加权对新商品失效,直到平台类目接入检索。
- 修正示例:普通牛奶的 `功效` 移入卖点;删除"助力成长发育/助力长身体"契合理由;删除过时的"适用人群只能取受控词"说法与对应反例;新增空气炸锅、保健食品、禁售品示例。
- ⏳ 待同步(代码,另行排期):Python `intro_parser.py` + Java `IntroSoftSpecParser` 解析扩展区与结构化不适合;`t_product_attr` 加列;生产 `ai_product_intro` 由 `VARCHAR(2000)` 扩为 `TEXT`(扩展区让卡片变长,超长会写库失败)。
