# 商品认知录入(订正成规范 intro)

把用户**已提供**的商品认知,订正成**严格冒号软标签** intro 文本。核心是**规范化 + 合规改写**,不编造、不替商家补数据。产出直接用于 AI 导购商品知识库(系统 0 模型规则解析入库)。

## 职责边界(重要)
- ✅ 做:把运营给的内容**订正成规范格式**——写清定位、拆分核心卖点(主张)与关键事实(客观)、标 `(来源)`/`[推断]`、规格/型号/年龄/资质/卖点依据归入扩展区、能力/契合理由归类、合规红线改写、风险判定、必填/阈值校验。
- ❌ 不做:**不编造运营没给的事实、卖点、参数、型号、资质编号**;不替商家"脑补"商品信息,不换算单位。缺的(尤其必填)只**提示运营补原始信息**,不自行填。
- 拿不准某条是卖点还是事实、事实来源是什么、某个数值真假 → **问运营**,不猜着写。

## 何时用
- 用户说"帮我把这个商品整理成认知卡 / 规范简介 / 录入格式"
- 用户要按软标签格式写 `ai_product_intro`
- 不是让你推荐/比价商品——那是导购能力,不走本 skill

## 契约与示例(按需读,勿凭记忆)
- **格式契约(唯一事实源)**:`规范.md` —— 标签全集(基础区 §2 + 扩展区 §2.2)、标签顺序(§1.1)、定位写法与事实来源列表(§4)、合规红线(§5)、风险判定(§5.1)、判定阈值(N≥3)。开始前先读它。
- **产出样例**:`examples.md` —— 水牛奶 / 土鸡蛋 / 5号电池 / 空气炸锅 / 保健食品 + 反例。

## 交互流程
1. 先让运营提供/粘贴商品信息(卖点、事实、参数、人群、场景、关键词等**已有的**);信息够就直接订正,不要替运营想内容。
2. **风险判定**(`规范.md` §5.1):禁售品(药品/烟草/电子烟等)直接拒绝录入;需资质品类提醒补 `资质：`,不补也照常出卡,但输出前提醒一句。
3. **定位必填**(`规范.md` §4 规则 5):写成"关键特征 + 商品本体通名 + 适合谁/场景",本体要写对;运营说不清本体就先追问,不出卡。
4. 把运营给的内容**订正归类**到 `规范.md` 的对应标签:
   - 核心卖点(营销主张)与关键事实(客观可核实)必须分开;事实来源只能取固定列表(包装/配料表/营养成分表/铭牌/说明书/检测报告/商家口述),商家口述或运营明确说是推断的标 `[推断]`。
   - 参数、型号、适用年龄、资质、卖点依据写进**扩展区**(`规范.md` §2.2),放在 `商品名称：` 之后、`定位：` 之前。
   - 能力写 `能力名(证据1；证据2)`(证据可省;旧式 `能力名<-证据` 仍兼容),须由运营给的卖点/事实支撑,不凭空造证据。
   - 适用人群/场景用大白话自由填;`功效` 只限保健营养类,普通商品的"功效"改写进核心卖点。
   - `不适合` 能归类的写 `过敏原=X`/`人群=X`/`年龄=X岁以下`,其余写大白话。
   - 不写 `类目：`,类目由系统判定。
   > 搜索友好度:`定位`/`需求`/`用户会问` 最能让商品**被买家搜到**(见 `规范.md` §7);运营有就尽量引导补上——但**用大白话跟商家讲好处(别用"向量/召回"等术语)**,也**不替运营编造**。
5. 遇合规问题(绝对化用语/超范围功效/医疗用语/儿童生长发育宣称)当场提醒并改写:违规词进 `禁用表达`,合规说法进 `允许表达`。
6. 校验:定位已写;基础区标签数 ≥3 且核心卖点或关键事实非空;**不足时提示运营补充原始信息,不自行编造**。
7. 输出最终 intro(按 `商品名称 → 扩展区 → 基础区` 顺序,只输出那几行标签,每行行首是标签名,不加解释、不加代码块),末尾问一句"需要调整哪一项?"。

## 输出后
提示用户:把这段文本**原样复制**到商品平台的「商品简介 / ai_product_intro」字段。

## 同源约束
标签名/别名/阈值改动,须同步 `规范.md` + `system-prompt.md` + Python `intro_parser.py` + Java `IntroSoftSpecParser`(见 `changelog.md`)。扩展区标签目前只存原文、解析器尚未支持,上线时按 `规范.md` §2.2 实现。
