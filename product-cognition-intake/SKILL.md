# 商品认知录入(订正成规范 intro)

把用户**已提供**的商品认知,订正成**严格冒号软标签** intro 文本。核心是**规范化 + 合规改写**,不编造、不替商家补数据。产出直接用于 AI 导购商品知识库(系统 0 模型规则解析入库)。

## 职责边界(重要)
- ✅ 做:把运营给的内容**订正成规范格式**——写清定位、拆分核心卖点(主张)与关键事实(客观)、标 `(来源)`/`[推断]`、规格/型号/年龄/资质/卖点依据归入扩展区、能力/契合理由归类、合规红线改写、风险判定、必填/阈值校验。
- ❌ 不做:**不编造运营没给的事实、卖点、参数、型号、资质编号**;不替商家"脑补"商品信息,不换算单位。缺的(尤其必填)只**提示运营补原始信息**,不自行填。
- 拿不准某条是卖点还是事实、事实来源是什么、某个数值真假 → **问运营**,不猜着写。
- **没有就不写**:没给的标签整行不写,不写 `待确认`/`未知`/`默认` 等占位值;原始资料里的占位(规格 `默认`、品牌空)也视同没给。
- **无法追问时**(批量/表格导入/要求直接出结果):拿不准的不写;必填缺失就不出卡,只输出"资料不足,暂不生成知识卡"的说明(缺什么、补什么、不要粘贴),格式见 `规范.md` §4 规则 9。
- **准入先判**:非实物占位(积分/激活/客服专线/纯链接)、虚拟卡券(购物卡/兑换券)、无服务项的服务、只有"以当日为准"的餐饮 → 一律不出卡,但**必须输出说明,不能留空**(见 `规范.md` §5.2)。同一批数据里同一商品只允许一个结论。

## 何时用
- 用户说"帮我把这个商品整理成认知卡 / 规范简介 / 录入格式"
- 用户要按软标签格式写 `ai_product_intro`
- 不是让你推荐/比价商品——那是导购能力,不走本 skill

## 契约与示例(按需读,勿凭记忆)
- **格式契约(唯一事实源)**:`规范.md` —— 标签全集(基础区 §2 + 扩展区 §2.2)、标签顺序(§1.1)、定位写法与事实来源列表(§4)、合规红线(§5)、**准入判定(§5.2)**、**品类基线禁用表达(§5.3)**、风险判定(§5.1)、判定阈值(N≥3)。开始前先读它。
- **产出样例**:`examples.md` —— 水牛奶 / 土鸡蛋 / 5号电池 / 空气炸锅 / 保健食品 + 不出卡与服务类样例 + 反例。

## 交互流程
0. **先判准入**(`规范.md` §5.2):按商品形态判"能不能出卡"。非实物占位/虚拟卡券/无服务项的服务/只有"以当日为准"的餐饮 → 不出卡,直接输出说明,后续步骤跳过。判定顺序:**准入 → 风险 → 必填 → 触发字段 → 合规闭环 → 自检**。
1. 先让运营提供/粘贴商品信息(卖点、事实、参数、人群、场景、关键词等**已有的**);信息够就直接订正,不要替运营想内容。
2. **风险判定**(`规范.md` §5.1):禁售品(药品/烟草/电子烟等)直接拒绝录入;需资质品类提醒补 `资质：`,不补也照常出卡,但输出前提醒一句。
3. **定位必填**(`规范.md` §4 规则 5):写成"关键特征 + 商品本体通名 + 适合谁/场景",本体要写对;运营说不清本体就先追问,不出卡。
4. 把运营给的内容**订正归类**到 `规范.md` 的对应标签:
   - 核心卖点(营销主张)与关键事实(客观可核实)必须分开;事实来源只能取固定列表 9 项(包装/配料表/营养成分表/铭牌/说明书/检测报告/详情页/标题/商家口述),商家口述或运营明确说是推断的标 `[推断]`。**同一事实有多个来源时取优先级最高的**(铭牌>说明书>检测报告>营养成分表>配料表>包装>详情页>标题>口述),不得把已核实的参数降级成"标题"或漏写(`规范.md` §4 规则 1)。
   - 参数、型号、适用年龄、资质、卖点依据写进**扩展区**(`规范.md` §2.2),放在 `商品名称：` 之后、`定位：` 之前。
   - 能力写 `能力名(证据1；证据2)`(证据可省;旧式 `能力名<-证据` 仍兼容),须由运营给的卖点/事实支撑,不凭空造证据。
   - 适用人群/场景**有依据才写**:资料原文写了,或规格决定只给这类人用;"也适合"的不写,通用商品不写人群(不写"成人"凑数)。见 `规范.md` §4 规则 4。`功效` 只限保健营养类,普通商品的"功效"改写进核心卖点。
   - `不适合` 能归类的写 `过敏原=X`/`人群=X`/`年龄=X岁以下`,其余写大白话。
   - **触发式必填**(`规范.md` §4 规则 11):按品类把该有的字段补齐——食品要有禁用/允许表达,含酒精要写未成年人/孕妇/驾车人员,保健食品要有资质+功效+固定允许表达,含检测认证的要有来源。**过敏原与法定禁忌可以从配料/成分推定**,不算编造。
   - 不写 `类目：`,类目由系统判定。
   - `需求`/`用户会问`/`关键词`/`能力`/`差异化`/`契合理由`/`允许表达`/`使用建议`:**换说法可以,加信息不行**,逐句过三问——本体(买家这么问,它是正确答案吗)、强度(比原文更强吗)、对比(拿谁比、依据在哪)。见 `规范.md` §4 规则 10。
   > 搜索友好度:`定位`/`需求`/`用户会问` 最能让商品**被买家搜到**(见 `规范.md` §7);运营有就尽量引导补上——但**用大白话跟商家讲好处(别用"向量/召回"等术语)**,也**不替运营编造**。
5. 遇合规问题(绝对化用语/超范围功效/医疗用语/儿童生长发育宣称)当场提醒并改写:违规词进 `禁用表达`,合规说法进 `允许表达`;**命中品类按 `规范.md` §5.3 基线补全**,不靠临场发挥。
6. **合规闭环**(`规范.md` §4 规则 12):把 `禁用表达` 逐条与本卡所有正向字段(核心卖点/关键事实/能力/差异化/契合理由/需求/关键词/允许表达)做包含式比对,命中即删——**严禁禁用词又出现在卖点里**。
7. 输出前自查(不写进输出):定位已写;基础区标签数 ≥3 且核心卖点或关键事实非空;没有占位值;**触发字段齐全**;生成类字段都过了依据链三问;来源没有降级;**不足时提示运营补充原始信息,不自行编造**(无法追问则不出卡)。
8. 输出最终 intro(按 `商品名称 → 扩展区 → 基础区` 顺序,只输出那几行标签,每行行首是标签名,不加解释、不加代码块),末尾问一句"需要调整哪一项?"。

## 输出后
提示用户:把这段文本**原样复制**到商品平台的「商品简介 / ai_product_intro」字段。

## 同源约束
标签名/别名/阈值改动,须同步 `规范.md` + `system-prompt.md` + Python `intro_parser.py` + Java `IntroSoftSpecParser`(见 `changelog.md`)。扩展区标签目前只存原文、解析器尚未支持,上线时按 `规范.md` §2.2 实现。
